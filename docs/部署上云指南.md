# 智慧医疗平台 · 服务器上云部署指南（Ubuntu 22.04）

> 适用：把本项目从本地 `runserver` 搬到一台云服务器上，通过公网 IP（或域名）访问。
> 架构：**Nginx（80 端口，托管静态/媒体 + 反向代理）→ Gunicorn（127.0.0.1:8000，跑 Django）→ MySQL（本机 3306）**。
> 全程不把数据库密码、API Key、`.env` 提交进 Git。

---

## 0. 准备工作

1. 买一台学生轻量应用服务器（阿里云 / 腾讯云均可）：
   - 系统镜像选 **Ubuntu 22.04 LTS**；
   - 配置 1 核 2G 以上即可跑演示；
   - 记下**公网 IP**（例如 `123.45.67.89`）。
2. 在控制台「防火墙 / 安全组」放行端口：`22`（SSH）、`80`（HTTP）；以后上 HTTPS 再放 `443`。**不要把 8000、3306 对公网开放**。
3. （可选）有备案域名就解析 A 记录到该 IP；没有域名，直接用公网 IP 访问也可以。

---

## 1. 登录服务器并初始化系统

本地终端 SSH 登录（用户名默认 `ubuntu` 或 `root`，以控制台提示为准）：

```bash
ssh root@123.45.67.89
```

更新系统并安装基础依赖：

```bash
apt update && apt upgrade -y
apt install -y python3 python3-venv python3-pip mysql-server nginx git
```

> 本项目用 `pymysql` 驱动，**不需要**编译安装 mysqlclient，也不需要系统层 `libmysqlclient-dev`。

---

## 2. 拉取代码并建虚拟环境

```bash
# 拉代码到 /opt
mkdir -p /opt && cd /opt
git clone https://github.com/GTY123moon/software-eng-project.git medical-platform
cd /opt/medical-platform

# 建虚拟环境
python3 -m venv venv
source venv/bin/activate

# 装依赖
pip install --upgrade pip
pip install -r requirements.txt
```

> 若服务器 Git 拉取慢，也可在本地打包后 `scp` 上传到 `/opt/medical-platform`。

---

## 3. 初始化数据库

### 3.1 启动 MySQL 并建库

```bash
systemctl enable --now mysql
mysql_secure_installation   # 按提示设置 root 密码、移除匿名用户（演示环境可一路 Y）
```

登录 MySQL，建库（`utf8mb4` 以支持中文）：

```sql
CREATE DATABASE medical_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
-- 演示可直接用 root；想建专用用户则执行：
-- CREATE USER 'medical'@'localhost' IDENTIFIED BY '你的数据库密码';
-- GRANT ALL PRIVILEGES ON medical_platform.* TO 'medical'@'localhost';
-- FLUSH PRIVILEGES;
```

### 3.2 按顺序灌入业务表与演示数据

> 业务 14 张表由 SQL 直建（Django `managed=False`），**不要执行 `makemigrations`**。
> 顺序不能乱：建表 → 基础种子 → 业务补充 → 值班轮询模板。

```bash
cd /opt/medical-platform

# 下面把 用户名/密码换成上面设置的；-p 后紧跟密码（无空格）
mysql -uroot -p'你的MySQL密码' < docs/sql/create_tables.sql
mysql -uroot -p'你的MySQL密码' < docs/sql/seed_data.sql
mysql -uroot -p'你的MySQL密码' < docs/sql/seed_business_extra.sql
mysql -uroot -p'你的MySQL密码' < docs/sql/seed_duty_rotation.sql
```

### 3.3 建 Django 内置框架表（session / auth / admin 等）

```bash
source venv/bin/activate
python manage.py migrate
```

> 这一步只创建 Django 自带的框架表，不会改动上面 SQL 建好的业务表。

## 4. 写生产环境配置（`.env`）

项目配置读取环境变量；在项目根目录复制样例并填写：

```bash
cd /opt/medical-platform
cp .env.example .env
```

编辑 `.env`：

```bash
nano .env
```

按实际填写（示例）：

```ini
DJANGO_DEBUG=0
DJANGO_ALLOWED_HOSTS=127.0.0.1,123.45.67.89
DJANGO_SECRET_KEY=用下面命令生成的随机串
MYSQL_NAME=medical_platform
MYSQL_USER=root
MYSQL_PASSWORD=你的MySQL密码
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
AI_BASE_URL=https://api.siliconflow.cn/v1/chat/completions
AI_API_KEY=
AI_MODEL=Qwen/Qwen2.5-7B-Instruct
```

生成新的生产 `SECRET_KEY`（不要沿用代码里的开发默认值）：

```bash
source venv/bin/activate
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

把输出的随机串填到 `DJANGO_SECRET_KEY`。

> 说明：`.env` 已被 `.gitignore` 忽略，不会进仓库。AI Key 留空也能跑，三条 AI 链路会自动降级本地规则。

### 4.1 收集静态文件

```bash
python manage.py collectstatic --noinput
```

生成的 `staticfiles/` 目录交给 Nginx 直接托管。

## 5. 配置 Gunicorn（systemd 托管）

复制服务样例到 systemd 目录：

```bash
sudo cp deploy/medical-platform.service /etc/systemd/system/medical-platform.service
```

按实际路径核对文件内容（`/opt/medical-platform`、venv 路径、运行用户）：

```bash
sudo nano /etc/systemd/system/medical-platform.service
```

启动并设为开机自启：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now medical-platform
sudo systemctl status medical-platform
```

看运行日志（报错时排查用）：

```bash
journalctl -u medical-platform -f --no-pager
```

手动验证 Gunicorn 是否能回包：

```bash
curl -I http://127.0.0.1:8000/
# 应返回 302（根路径跳转到身份选择页）
```

---

## 6. 配置 Nginx 反向代理

复制站点样例：

```bash
sudo cp deploy/nginx-medical.conf /etc/nginx/sites-available/medical-platform
sudo nano /etc/nginx/sites-available/medical-platform
```

把 `server_name` 改成你的公网 IP 或域名；确认静态/媒体路径与实际一致：

```nginx
server_name 123.45.67.89;
location /static/ { alias /opt/medical-platform/staticfiles/; }
location /media/  { alias /opt/medical-platform/media/; }
location / { proxy_pass http://127.0.0.1:8000; }
```

启用站点并校验、重载：

```bash
sudo ln -sf /etc/nginx/sites-available/medical-platform /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

> 默认 `sites-enabled` 里若还有 `default` 站点占用 80，可 `sudo rm /etc/nginx/sites-enabled/default` 后重载。

## 8. 日常运维

拉取新代码后的发布步骤：

```bash
cd /opt/medical-platform
git pull origin main
source venv/bin/activate
pip install -r requirements.txt        # 依赖有变化时
python manage.py migrate               # 仅框架表变化时；业务表仍由 SQL 维护
python manage.py collectstatic --noinput
sudo systemctl restart medical-platform
```

常用排查命令：

```bash
sudo systemctl status medical-platform      # 应用状态
journalctl -u medical-platform -n 100       # 应用最近日志
sudo nginx -t && sudo systemctl reload nginx
```

## 9. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 浏览器 502 Bad Gateway | Gunicorn 没起来或崩了；看 `journalctl -u medical-platform`，常见是 `.env` 数据库密码错、依赖没装全 |
| 页面能开但 CSS/JS 404 | 没跑 `collectstatic`，或 Nginx `/static/` 路径指向的目录不对 |
| 上传的聊天图片打不开 | Nginx `/media/` 别名路径不对，或 `media/` 目录权限不足（`chown -R www-data:www-data media`） |
| 400 Bad Request (DisallowedHost) | `.env` 里 `DJANGO_ALLOWED_HOSTS` 没填当前访问的 IP/域名 |
| 数据库 Access denied | `.env` 里 `MYSQL_USER/MYSQL_PASSWORD` 与 MySQL 实际账号不一致 |
| AI 卡片显示「服务暂时不可用」 | 未填 Key、远程限流或超时；属自动降级，不影响主流程，填可用 Key 后恢复 |
| 静态文件/上传目录权限 | 项目目录归运行用户：`sudo chown -R www-data:www-data /opt/medical-platform` |

## 10. 附录：可选 Docker Compose 方式（备选）

如果不想手动装 MySQL/Nginx，可用容器编排一键起 Web + MySQL；下面是思路，按需落地：

- `web` 容器：`gunicorn medical_platform.wsgi:application --bind 0.0.0.0:8000`，挂载代码与 `media/`，读环境变量；
- `db` 容器：MySQL 8，`utf8mb4`，数据卷持久化；
- 首次进入 `web` 容器执行上面第 3 节的 SQL 灌入与 `migrate`；
- 宿主机 80 端口映射到 Web，静态文件可在容器内 `collectstatic` 后由 Nginx 或 Web 托管。

> 面试讲解时，手动「Nginx + Gunicorn + MySQL」这套链路更能说清各组件职责；Docker 可作为了解项补充。

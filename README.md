# 智慧医疗在线问诊与处方流转平台

> 软件工程实验项目 · Django 单体分层（MTV）· B/S 架构

## 一、项目背景

本系统面向医院药房及临床科室，支持线上图文及媒体问诊，为行动不便、路途较远或慢性病需要定期复诊的患者提供电子处方流转服务；患者凭电子处方到院药房取药或到社会药店购药，节约患者就医时间与医疗资源。

---

## 二、业务目标

### 2.1 系统用户

- **患者**：发起问诊、查看处方、凭处方到院取药或外购
- **医生**：线上接诊、回复病情、开具处方、按排班承担白天坐诊与夜间值班任务
- **药师**：审核处方、配药发药
- **管理员**：维护账号与药品目录、配置医生值班排班、操作日志审计

### 2.2 解决问题

- 患者不用跑医院就能完成问诊、开方、取药全流程
- 医生线上接诊，AI 自动整理病历，减少重复问诊工作量，提高接诊效率
- 药师线上审方配药，AI 自动校验药物风险，缩短取药等待时间
- 覆盖全时段轻症咨询需求，急症自动引导线下就医，避免非工作时间无人响应

### 2.3 核心价值

- 缩短就医取药流程，减少患者往返医院次数
- 方便慢性病复诊、时间不充裕、行动不便的患者
- 节约医疗资源，提升药房与科室运转效率
- 通过 AI 前置辅助实现智慧诊疗，从人工流程升级为 AI 辅助的闭环服务

## 三、非功能需求

| 属性 | 要求 |
|---|---|
| 并发性能 | 支持 1000+ 用户同时在线，问诊消息响应时间 < 2 秒，AI 预问诊接口响应 < 1 秒 |
| 可用性 | AI 引擎 7×24 小时全时段值守；常规坐诊医生 8:00-22:00 在线接诊，夜间 22:00 - 次日 8:00 安排值班医生轮值，普通咨询响应 ≤ 30 分钟，识别到急症自动引导患者线下就医；系统故障恢复时间 < 30 分钟 |

| 兼容性 | 支持 PC 浏览器访问，界面适配主流分辨率 |

## 四、核心概念

### 4.1 处方
处方不是普通药单，必须经过完整流程：医生开具 → AI 校验 → 药师审核 → 患者凭电子处方取药或外购，全程状态可控。

### 4.2 问诊
问诊是医患图文及媒体消息会话，不是即时聊天，有明确的开始和结束状态，会话记录可回看；问诊全程由 AI 自动整理要点，区分白天坐诊与夜间值班接诊场景。

### 4.3 审方
药师审查处方用药合理性，包括配伍禁忌、用法用量、适应症与诊断匹配度；AI 先完成初筛标记风险，药师做最终人工判断；审方不通过则退回医生修改。

### 4.4 AI 智能辅助
AI 是系统的辅助组件，不替代医生做最终诊疗判断。在流程节点上提供辅助：预问诊阶段引导患者结构化描述病情、自动识别急症风险、生成病情摘要供医生参考；开方 / 审方阶段自动校验药物配伍禁忌与剂量异常，减少人工重复劳动。

## 五、功能范围

| 模块 | 功能 |
|---|---|
| 用户注册登录 | 身份选择入口；患者自助注册并手机号密码登录；职工（医生/药师/管理员）后台开通账号，内部密钥登录，按角色路由到对应工作台 |
| 线上问诊 | 患者选医生、AI 引导式预问诊采集病史与症状、AI 风险分级与病情摘要生成、图文及媒体消息收发、会话记录自动整理、夜间咨询自动派单给值班医生 |
| 处方开具 | 医生参考 AI 病情摘要、检索药品、添加用法用量、AI 自动校验药物禁忌后提交处方 |
| 处方审核 | 药师参考 AI 初筛风险提示，审核通过 / 驳回并填写理由，高风险处方由药师重点复核，结果通知医生 |
| 处方取药 | 患者选择取药方式（院药房取药 / 社会药店购药），查看处方与取药状态 |
| 配药发药 | 药师配药扣减库存、代煎登记、发药确认 |
| 后台管理 | 管理员维护账号、药品目录，配置医生值班排班，查询操作日志与 AI 转诊风险记录 |

## 八、本地启动

> 详细操作步骤见 `docs/组员本地运行指南.docx`。每个人在自己本机 MySQL 建独立库，数据库不共享。

1. 安装依赖：

```
python -m pip install -r requirements.txt
```

2. 初始化数据库：在本机 MySQL 按顺序执行 `docs/sql/` 下脚本（`create_tables.sql` → `seed_data.sql` → `seed_business_extra.sql`），创建 `medical_platform` 库与 14 张表并灌入演示数据（管理员 2 / 患者 100 / 医生 100 / 药师 100 / 药品 95，及排班、问诊、处方等业务数据）。`create_tables.sql` 自带 `DROP DATABASE` 重建，后两个种子脚本可重复执行（先清空再灌入）。

   Windows 命令行（在项目根目录执行；若 `mysql` 未加入 PATH，改用 MySQL 安装目录 `bin\mysql.exe` 的全路径）：

   ```
   mysql -uroot -p < docs/sql/create_tables.sql
   mysql -uroot -p < docs/sql/seed_data.sql
   mysql -uroot -p < docs/sql/seed_business_extra.sql
   ```

3. 填写本机私有配置：把 `medical_platform/local_settings.example.py` 复制为同目录 `local_settings.py`，填入本机 MySQL 密码（AI Key 可选，不填走本地降级）。`local_settings.py` 已被 `.gitignore` 排除，不提交。

4. 初始化 Django 内置框架表：业务 14 张表由 SQL 直建（`managed=False`），**不要**执行 `makemigrations`；首次启动前执行一次 `python manage.py migrate`，创建 session / auth / admin 等内置框架表（登录态依赖 session 表），该操作不会改动业务表。

5. 启动开发服务器：

```
python manage.py runserver
```

浏览器访问 `http://127.0.0.1:8000`，根路径进入身份选择页；各端前缀：`/accounts/`、`/doctor/`、`/pharmacist/`、`/adminpanel/`。

登录口径：

- **患者**：自助注册，手机号 + 密码登录。演示患者账号：手机号 `13800000002`，密码 `demo123456`。
- **职工（医生 / 药师 / 管理员）**：账号由后台统一开通，不可自助注册；使用登记的工作手机号 + 内部密钥登录。演示内部密钥均为 `demo123456`：
  - 医生：`13700000083`
  - 药师：`13600000138`
  - 管理员：`13800000001`（后台账号 `admin`）

### 8.1 AI 大模型接入（可选，不配也能离线跑）

系统通过平台无关的 OpenAI 兼容接口接大模型，切换平台只改三个配置项，业务代码不动；未填 Key 或接口超时时，预问诊分级摘要、医生复核建议、处方预审三条链路自动降级本地规则，演示流程不报错。

**选型建议（课设演示）**：首推智谱 `glm-4.7-flash`——永久免费、中文表现好、响应快，注册开放平台即可领取 Key；现有默认端点与模型 ID 已配好，只需填 Key。其余平台对照如下：

| 平台 | 模型 ID | 接口地址（chat/completions 完整路径） | 备注 |
|---|---|---|---|
| 智谱（默认） | `glm-4.7-flash` | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | 永久免费，中文轻量，注册即给 Key |
| 硅基流动 | `Qwen/Qwen2.5-7B-Instruct` | `https://api.siliconflow.cn/v1/chat/completions` | 免费档，非思考链响应快，国内站需实名 |
| 阿里百炼 | `qwen-turbo` | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` | 按量付费，稳定 |
| 火山方舟 | `ep-xxxx`（接入点 ID） | `https://ark.cn-beijing.volces.com/api/v3/chat/completions` | 付费；fast 档位未开通时自动回退常规档 |

**配置方式**（二选一，环境变量优先于本地文件）：

- 在 `medical_platform/local_settings.py` 写（该文件已被 `.gitignore` 排除，不进仓库）：

```python
os.environ.setdefault('AI_BASE_URL', 'https://open.bigmodel.cn/api/paas/v4/chat/completions')
os.environ.setdefault('AI_API_KEY', '你的密钥')
os.environ.setdefault('AI_MODEL', 'glm-4.7-flash')
```

- 或在系统环境变量中设置同名 `AI_BASE_URL / AI_API_KEY / AI_MODEL`。

**连通性自测**：工程根目录执行 `python check_ai.py`，逐条打印配置识别、患者端分级摘要、医生端复核建议、处方草稿预审走的是远程平台还是本地降级；填好 Key 后重跑，远程条目应显示对应平台来源。

## 十、开发约定

- AI 为系统内部规则引擎组件，**不是外部 Actor**；AI 结果标注"仅供参考"，最终诊断与处方责任归执业医生，复核全程留痕。
- 状态枚举值（角色、问诊状态、处方状态、取药方式等）以 `docs/` 中的数据库表清单为准，不在代码里私自改写法。
- 公共表字段一旦定好不私自修改；确需调整表结构，先在组内沟通，由成员4 统一维护。
- 代码不提交本地数据库、缓存、密钥和个人 IDE 配置（见 `.gitignore`）。

# 药师跨角色业务联调指南

本轮沿用 14 张业务表与已有状态，不需要修改表、运行 migrate 或导入种子脚本。

## 1. 推荐：启动隔离联调服务

在 PowerShell 中执行：

```powershell
cd E:\Software\medical_system\software-eng-project
.\venv\Scripts\python.exe -B -m pharmacist.e2e_server
```

打开 http://127.0.0.1:8767/ 。这是同一个 Django 服务、同一个新建的 MySQL 测试库，
患者、医生、药师登录后都读写它。界面和业务视图与正常服务相同，没有模拟登录、接口或库存。
终端会打印随机库名 `test_pharmacist_...`；不会复制、修改 `medical_platform` 的数据。
外部 AI 在此隔离进程中关闭，实际走项目已有的本地降级，页面如实标记“超时降级”。

测试账号为合成演示资料，来源为 `pharmacist/test_support.py` 中的 `TEST_PHONES`；

## 2. 正常流程（建议先在全新的隔离服务测试）

1. 患者登录，点击“线上问诊”，选择“测试内科”和唯一在线医生，点击“提交挂号”。
2. 回答预问诊，例如“轻微咳嗽两天，无其他症状”，点击“发送”，再点击“病情已补充完，生成评估”。
   应进入同一问诊的沟通页。
3. 退出并登录医生。接诊台点击该问诊，选择“采纳”并“提交复核”，进入图文沟通。
   选中的医生在患者挂号时已绑定此问诊，不必另造一个接诊接口。
4. 点击“结束问诊并给出处置建议”，填写测试诊断，选择“需要开具处方”，提交处置建议。
5. 开方页选择“联调药品甲”，数量 2、填写测试用法；“＋ 添加一行”，选择“联调药品乙”，
   数量 3、填写测试用法。保存草稿后进入独立预审页。
6. 记下页面处方号，点击“提交药师审核”，确认弹窗。处方从“草稿”变“待审核”，医生确认字段为 1。
   有 AI 风险提示时须使用明确的“已知悉风险，仍提交”入口。
7. 退出并登录药师。点击首页“待审核”统计或左侧“待审核处方”，打开同编号详情。
   应看到两项药品、数量、用法、测试患者、医生、诊断、预审与库存；点击“审核通过”。
   状态变“已通过”，尚未发药，库存仍为 100 / 100。
8. 退出并登录患者。“我的处方”→同编号“查看处方详情”。选择“院药房取药”。
   可为甲选择代煎、填写 2 剂；确认取药方式后状态为“待配药”。选择是一次确认，不能提交旧表单更改。
9. 退出并登录药师。“待配药处方”→同编号详情。先核对药品、数量、患者身份和库存。
   核对阶段不扣库存；实际完成交付时勾选确认，如有代煎还须确认代煎已完成，点击“确认实际发药”。
   状态应变“已完成”，取药状态为“已取药”，显示发药时间。库存应变 98 / 97。
10. 再登录患者，重开同张处方：应从数据库读取“已完成”“已取药”和发药时间。

三端编号的展示稍有不同：医生/患者的 `P000000001` 与药师的 `#1` 是同一个整数主键 1。
同时核对问诊、两项药名、数量 2/3 与诊断，避免看错旧记录。
这个编号也是本轮全新隔离库真实浏览器验收使用的正常流程示例；停止隔离服务后记录随测试库清理，
不代表业务库中编号 1 的旧种子处方。你新开服务并首次开方也会从该编号开始。

## 3. 驳回、修改、重提

1. 再发起一次新问诊并按上面步骤开方提交。记下新的处方号。
2. 药师打开待审核详情，填写具体驳回理由，点击“驳回处方”。空白、超长理由会被服务端拒绝。
3. 医生“我的处方”可见“已驳回”和理由。进入该处方，修改用法或药品后保存草稿。
   处方编号不变；重新运行预审，状态回草稿，医生确认清零。
4. 从预审页重新提交，再由药师在待审核列表打开同编号审核。旧详情页不能审核重提后的新版本。
5. 本轮真实浏览器验收还用 `P000000002` 走完驳回→修改重提→通过，随后选择社会药店外购。

驳回意见在修改期间继续显示，下一次药师审核替换当前结论；每一轮保存、提交、驳回、通过均有操作日志。
既有日志表不含完整意见历史字段，本轮不扩展数据库；它保留操作者、动作、目标处方和时间。

## 4. 社会药店与代煎

- 审核通过后选“社会药店购药”，页面显示“电子处方外购凭证”，状态保留“已通过”。
- 外购不进入院内待配药、不扣院内库存、不伪造实际已取药或发药时间，不提供院内代煎。
- 院内代煎以每项现有 `is_decoction` / `decoction_num` 登记，剂数为 1–9999 正整数。
- 现有状态没有独立“配药完成”。本轮采用已确认方案：核对不落完成状态，实际交付时一次事务扣库存并完成，
  不声称实现独立备药、库存预留、支付或配送子系统。
- 旧种子数据如果出现“社会药店 + 待配药”、未分配药师的待配药等矛盾组合，本轮不会自动修复或强制发药；
  请用新问诊产生的新处方验收，并由组长决定旧数据如何处理。

## 5. 核对库存与日志

最简单的核对：发药前后打开药师同张详情，看两项“库存”从 100/100 变成 98/97。
重复点击旧页面的发药操作不能再次扣减。

也可在 MySQL 图形工具中先选择终端显示的隔离库，**只运行 SELECT**：

```sql
SELECT p.presc_id, p.status, p.pickup_method, p.pickup_status, p.dispensed_at,
       i.drug_id, i.qty, d.drug_code, d.stock_qty
FROM prescription p JOIN prescription_item i ON i.presc_id=p.presc_id
JOIN drug d ON d.drug_id=i.drug_id
WHERE p.presc_id=1 ORDER BY i.drug_id;

SELECT operator_id, operator_type, action, target_id, created_at
FROM operation_log WHERE target_type='prescription' AND target_id=1 ORDER BY log_id;
```

## 6. 重新测试、停止服务与自动化

关闭服务时按 Ctrl+C；通过工具运行时也可在其标准输入发送 `stop`。
正常关闭会删除本次随机隔离库。重新运行启动命令获得全新数据，不必清理现有业务库或重跑种子。
异常强杀进程可能留下测试库；不要凭前缀批量删除，请记录准确库名再让维护者核对处理。

后端测试命令（新建/清理随机隔离库；不会执行 migrate 或种子脚本）：

```powershell
.\venv\Scripts\python.exe -B manage.py check
.\venv\Scripts\python.exe -B manage.py test pharmacist --settings=pharmacist.test_settings --verbosity 2
```

普通 `manage.py test pharmacist` 只运行原有无数据库测试，新集成测试会提示跳过。
隔离 MySQL 测试需要本机连接账号有创建/删除测试库的权限；不足时应报告权限，不能改用业务库测试。
现有 `fields.W342` 来自公共联合主键映射，继续保留；本轮按双键精确更新明细，未修改公共模型。

可选真实浏览器脚本：先启动隔离服务，再用**已有** Node.js / Playwright 执行
`node pharmacist/browser_workflow.cjs`。它使用本机 Edge，截图写到系统临时目录；不自动安装依赖。
需保证 Node 能找到预先安装的 `playwright`，可通过 `NODE_PATH` 指向其父目录。

## 7. 在已有业务库运行

只有你准备写入自己的演示业务数据时，才启动普通服务：

```powershell
.\venv\Scripts\python.exe -B manage.py runserver
```

把上述地址的 8767 换成 8000。现有演示账号来源为 `docs/sql/seed_data.sql` 及组长给定账号，
无需执行该脚本。不要在已有库中使用隔离联调的合成账号，除非维护者已独立创建它们。
本轮未在现有业务库执行网页登录或写入处方，只进行了只读结构核查。
